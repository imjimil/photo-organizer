## Anti-Patterns Verdict

**LLM assessment:** Does not read as generic AI slop. Gloock + Young Serif + OKLCH opal palette match PRODUCT.md and feel intentional (Cosmos-like, not SaaS-purple). Main risk is **glassmorphism density** (top rail, viewer chrome, selection bar) which borders on the skill's glass-as-default ban, but it serves the "luminous opal" brand.

**Deterministic scan:** Bundled detector unavailable (`detect.mjs` entrypoint missing). Manual code review used instead.

**Browser overlays:** Not run (no live dev server session in this audit).

## Overall Impression

Opal already has a coherent v6 design system and strong image-first layout. The biggest UX gaps are **search friction**, **silent failures**, and **undiscoverable power features** (drag-select, mobile sort), not visual taste.

## What's Working

1. **Iridescent token system** — OKLCH themes, mint accent for active sort, tile radius switching light/dark matches DESIGN.md precisely.
2. **Viewer craft** — Focus trap, pinch zoom, keyboard nav, related panel, and toast feedback feel production-grade.
3. **Selection workflow** — Selection bar, drag-select hook, and bulk album picker are thoughtful for a 25k library.

## Priority Issues

### [P1] Search requires manual submit
- **Why:** Users expect type-to-search (especially after OCR). Extra button click adds friction on every query.
- **Fix:** Debounced search on input + keep Enter; show inline loading in results area.
- **Suggested command:** `impeccable craft search`

### [P1] Silent API failures
- **Why:** `catch () {}` in App.tsx for create album, stats, search leaves users guessing when actions fail.
- **Fix:** Toast or inline error banners; retry on grid already good — extend pattern app-wide.
- **Suggested command:** `impeccable harden App`

### [P2] No library empty / first-run state
- **Why:** After indexing CLI, users opening the app see blank grid with no next step.
- **Fix:** Empty state with "Run index" hint, link to docs, or sample discover prompt.
- **Suggested command:** `impeccable onboard library`

### [P2] Mobile library missing Shuffle sort
- **Why:** Recent/Shuffle only in desktop TopNav; mobile users can't shuffle 25k images.
- **Fix:** Add sort toggle to MobileHeader on library view.
- **Suggested command:** `impeccable adapt TopNav`

### [P2] Power features undiscoverable
- **Why:** Drag-select, `/` shortcut, and album reorder hint are invisible to most users.
- **Fix:** One-time contextual hints (dismissible) or empty-state tips, not a tutorial modal.
- **Suggested command:** `impeccable onboard selection`

## Persona Red Flags

**Alex (Power User):** Search submit button blocks fast iteration. Album create failure gives no feedback. Would love command palette or recent searches.

**Jordan (First-Timer):** Discover says "tap, drag, swipe" but swipe affordance is subtle. Filters panel jargon ("Visual only", "Match %") needs plainer labels. Icon-only mobile nav has labels (good) but Select button purpose unclear until tapped.

**Sam (Accessibility-first):** Discover front card `aria-label="Next image"` is wrong semantics. Hard-coded `#e85d5d` delete color may fail contrast in dark mode.

## Minor Observations

- DESIGN.md mentions collections strip under library rail; app uses separate Collections tab instead (doc drift).
- Search filters UI breaks visual language (boxed inputs vs editorial search field).
- Tile-rise cascade on infinite scroll may jank with very large libraries.
- `LibraryBar.tsx` reduced to types only — dead import path in design doc.
